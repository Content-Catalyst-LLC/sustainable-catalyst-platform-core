# Platform Core v4.12.0 — Context Retrieval & Relevance Intelligence

## Purpose

v4.12.0 makes the governed v4.11 contextual-memory layer retrievable without collapsing contextual relevance into epistemic authority. It defines query, candidate, relevance-signal, ranking, provenance, and snapshot contracts that downstream products can use consistently.

## Reference retrieval

The reference query asks what context should be retrieved when reviewing whether the existing ministry-agency continuity hypothesis should inform a cross-language policy analysis. Candidate generation considers all six v4.11 memory objects. Explainable relevance ranking prioritizes the continuity hypothesis, multilingual governance divergence, and ministry uncertainty while retaining unresolved references and qualifications.

## Relevance signals

The reference profile uses semantic-anchor match, preferred-memory-kind match, scope match, contextual-link support, qualification preservation, unresolved-context materiality, and current-revision identity. Signal weights and contributions are explicit and reproducible.

## Epistemic boundaries

A high relevance score is not a truth score, evidence weight, source-authority score, credibility score, equivalence assertion, or identity claim. Provenance improves traceability, not truth. Scope proximity improves contextual fit, not authority. Retrieval does not mutate contextual memory, Context Graph, Identity Graph, Evidence Graph, or Knowledge Graph.

## Persistence

No database migration is required in v4.12.0. The release defines portable retrieval contracts and deterministic reference snapshots on top of the v4.11 memory foundation.
